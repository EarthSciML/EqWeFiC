# Cold-season Noah SCM reference run (stage 1), 2026-09-22

Stage-1 reference data for the parts of **Noah** (`sf_surface_physics = 2`) that no
existing EqWeFiC reference run reaches: the **snow pack** (`SNOPAC`, `SNOWPACK`,
`SNOW_NEW`, `SNFRAC`, `ALCALC`) and the **frozen-soil sink** (`SNKSRC`, `FRH2O`,
`TMPAVG`, `TBND`, called from `HRT`).

Every case behind the Noah components committed earlier on 2026-09-22
(`components/land_surface/noah/`, 448 assertions drawn from
`data/eqwefic/dumps/chem170_wrf`) is above freezing and snow-free.  Measured over all
16 of those dumps with `noahcold_scm/classify.py`: **snow pack present 0 steps, snowmelt
0, snowfall 0, frozen soil layers 0, soil ice changing 0**.  So these paths were
**untested, not merely unimplemented** — a wrong transcription would not have gone red.

`data/eqwefic/...` below means the disk-backed tree
`/projects/illinois/eng/cee/ctessum/ctessum/data/eqwefic/`, not this repo.

## Why an idealized column and not a real winter run

- The Noah components already in the repo are referenced against `em_scm_xy` dumps of
  exactly this shape, so new regimes drop into the existing `tests/*_inputs.esm`
  machinery with no new tooling.
- There is no winter real-data case to reuse: the only real-data domain in the project
  is 2012-06-25 (summer), and the ERA5 intermediate files behind its `met_em` files are
  gone, so a winter domain would have meant a fresh ERA5 download.
- A column lets the branches be *driven on purpose* — ascent to make it snow, warm
  advection to melt it — instead of hoping a real domain samples them at the dumped
  points.  Four 48 h columns cost about 6 minutes each.

The cost of that choice is in "What this does not cover".

## The two WRF changes this needed, and why they are initialisation only

`dyn_em/module_initialize_scm_xy.F` hard-wires `grid%snow(i,j) = 0.` for every
idealized column, so **no `em_scm_xy` run can start with a snow pack** — which is why
these paths have never been exercised.  The branch adds an `&scm` namelist variable
`scm_snow` (kg m-2 SWE, default **0.0**, so an unset namelist reproduces stock WRF
exactly) and sets `grid%snow` from it.

It must also set `grid%snowh`.  `phys/module_physics_init.F:318` declares
`FNDSNOWH` as a **PARAMETER `.true.`**, so `LSMINIT`'s "SNOW HEIGHT NOT FOUND - VALUE
DEFINED IN LSMINIT" fallback (`module_sf_noahdrv.F:2140-2148`, `SNOWH = SNOW*0.005`)
is dead code and never runs.  With `SNEQV > 1e-7` and `SNOWH = 0`, `SFLX` computes
`SNDENS = SNEQV/SNOWH` (`module_sf_noahlsm.F:509`) and aborts in
`'Physical snow depth is less than snow water equiv.'`.  The branch therefore sets
`grid%snowh = scm_snow * 0.005`, i.e. LSMINIT's own 200 kg m-3 new-snow density.
Recorded as FORTRAN_BUGS N93.

**No physics was touched.**  `phys/module_sf_noahlsm.F` and every other physics file
are byte-identical to upstream; the instrumentation lives in a build-time copy used
only by the kernel driver (below).

## The four cases

All four: `em_scm_xy`, 59 layers to `ztop` = 20 km, `dx = dy` = 20 km, `dt` = 60 s,
48 h from 2000-02-20 12 UTC, 44.0 N / 96.0 W, Noah on **silt loam (`scm_isltyp` = 4),
dryland cropland (`scm_lu_index` = 2), `vegfra` 50 %** — the same soil and vegetation as
the warm `chem170_scm` run, so only the cold physics differs.  `scm_force = 1` with
`scm_vert_adv`; chemistry off; WSM6, RRTM, Dudhia, sfclayrev, YSU, New Tiedtke as in the
warm run.

Sounding: theta 265 K at the surface, 3 K/km to 2 km, 4.5 K/km to 9 km, 15 K/km above;
RH 92 % below 5 km (ice-supersaturated at these temperatures, so ascent snows readily).
Column precipitable water 4.6 mm — winter is dry, and that is the accumulation limit.

| case | initial snow | soil | forcing | what it is for |
|---|---|---|---|---|
| **A** | none | 263/266/270/272.5 K, theta = 0.30 | ascent to 4 cm s-1, 4-20 h | bare frozen ground, snow onset onto bare soil, accumulation, partial cover |
| **B** | 60 kg m-2 (30 cm) | same | brief ascent, then +14 K warm advection (3 h relaxation) | full cover, deep pack, melt under warm air |
| **C** | 5 kg m-2 | 272.0/272.4/272.8/273.0 K, theta = 0.20 | +18 K warm advection (2 h relaxation) | melt, soil thaw and refreeze |
| **D** | 0.05 kg m-2 | same as C | same as C, **dry sounding** (RH 30 %) | the pack disappearing, then bare frozen ground |

Three things had to be learned from the probe passes rather than assumed:

- **A deep pack insulates the soil so well that it never thaws.**  Case B's air reaches
  277 K while its top soil layer stays at 264 K and all four layers stay frozen for the
  whole 48 h.  That is correct physics, and it is why the thaw needed case C.
- **A wet column will not let a thin pack disappear.**  The first case D kept re-snowing:
  precipitation aloft still arrives frozen (`FFROZP` comes from WSM6's snow ratio) even
  with surface air near 280 K.  Making the sounding dry (nothing to condense) was what
  let the pack go.  A 1 kg m-2 dry pack still did not vanish — nightly frost deposition
  replaced the daytime melt and sublimation, holding it at 0.5 mm indefinitely — so
  case D starts from a 0.05 kg m-2 trace, which melts out at step 1000.
- **`SNCOVR` never reads 1.0 even with a pack far above `SNUP`.**  `SFLX` caps SNFRAC's
  output at 0.98 (`module_sf_noahlsm.F:588`).  Case B's 60 kg m-2 against `SNUP` = 0.04 m
  does take SNFRAC's `SNEQV >= SNUP` saturation branch; it reports 0.98, which also
  selects the `SNCOVR > 0.97` snow-conductivity branch at `:627` that no other case reaches.

## Coverage actually achieved

**84 dumps** (A 20, B 17, C 24, D 23), 3.6 MB, in
`data/eqwefic/dumps/noahcold_wrf/case*/`.  Steps were chosen by `select_steps.py` from
2880-step probe passes, each pick carrying a stated reason, with a 25-step minimum
separation so no two regimes are the same state to four digits.

Branch facts below are **read back out of the real64 replay's own publishers**, not
inferred from the inputs:

| branch | A | B | C | D | total |
|---|---|---|---|---|---|
| `SNOPAC` sub-freezing block (`T12 <= TFREEZ`) | 12 | 12 | 11 | 3 | **38** |
| `SNOPAC` melt block (`T12 > TFREEZ`) | 7 | 5 | 13 | 4 | **29** |
| `NOPAC` (no pack) | 1 | 0 | 0 | 16 | **17** |
| `FRH2O` path 1 (`FREE = SMC`) | 0 | 0 | 1 | 2 | **3** layer-calls |
| `FRH2O` path 2 (Newton converged) | 80 | 68 | 93 | 88 | **329** layer-calls |
| `FRH2O` path 3 (Flerchinger fallback) | 0 | 0 | 0 | 0 | **0** |

From the probe passes (2880 steps each), the regimes those dumps are drawn from:

| | A | B | C | D |
|---|---|---|---|---|
| snowfall (`prcp > 0`, `ffrozp > 0.5`) | 2045 | 599 | 388 | 0 |
| snowmelt (`snomlt > 0`) | 241 | 489 | 910 | 183 |
| sublimation (`esnow > 0`) | 1844 | 1156 | 1211 | — |
| frost / deposition (`etp < 0`) | 1035 | 24 | 1669 | — |
| partial cover `0 < sncovr < 1` | 2878 | 0 | 2880 | 2880 |
| full cover (SNFRAC saturation, capped 0.98) | 0 | 2880 | 0 | 0 |
| bare ground with frozen soil | 3 | 0 | 0 | 2327 |
| soil ice changing | 2880 | 2880 | 2808 | 2857 |
| soil partly thawed (`nfrozen < 4`) | 0 | 0 | yes | yes |

Case C is the freeze/thaw case: its top layer crosses 273.15 K (272.1 -> 274.8 K) during
the day and refreezes overnight, so both transitions are in one run.

**`FRH2O`'s path 1 is one or two steps wide, and that is physics, not a sampling
failure.**  `TMPAVG` holds `TAVG` on the freezing plateau for as long as a layer still
holds ice, so `TAVG > T0 - 1e-3` can only happen in the step where a layer's last ice
disappears.  `scan_tavg.py` replayed every third probe step of case D over 1700-2880 and
found exactly two such steps (1934, 1935; `TAVG` = 273.14907 and 273.14998 K against the
273.149 K threshold), and one in case C (2119).  All three are now in the dumped set.

## Replay agreement

`noah_driver` with the cold-path splices, both precisions, over all 84 dumps:

- **real32 driver vs the in-model dump: exactly zero** on every field of every step
  (`t1_out`, `eta`, `sheat`, `ssoil`, `etp`, `beta`, `esnow`, `snomlt`, `sncovr`,
  `sneqv_out`, `snowh_out`, `albedo_out`, `stc_out`, `smc_out`, `sh2o_out`, `et`, ...).
  So the dumps carry every input `SFLX` reads on the cold paths, and the driver is
  validated for them exactly as it was for the warm ones.
- **real64 vs in-model**, worst absolute over all cases: `flx3` 8.6e-4 W m-2 (on values
  1.9 to 266), `sheat` 6.8e-4 W m-2 (on 54 to 187), `ssoil` 2.9e-4 W m-2, `t1_out`
  4.3e-5 K.  That is real32 round-off of the in-model values, as for the warm cases.
- **Precision does not change any branch.**  `sno_branch`, `frz_path` and `frz_called`
  agree between the real32 and real64 replays at **every one of the 84 steps** — the
  same test the GWDO work ran, and the same answer.
- **Relative-to-field-max is misleading for a field that is near zero here**: case D's
  `runoff1` shows 2.3e-2 relative on a bare, dry column whose runoff is ~1e-6.  Use
  absolute bounds for those, as the GWDO notes also concluded.

**Reference tendencies must still come from the real64 replay at a small `ESM_DT`**, for
the reason the warm Noah work established: `SFLX` is an in-place step, so
`(x_out - x_in)/dt` at WRF's 60 s is off the dt -> 0 limit.  `replay.py` writes an
`r64s_*` pass at `ESM_DT = 0.01 s` beside the two dt = 60 s passes for exactly this.

## Instrumentation

Ten new grep-guarded splices, spliced by `kernels/noah_cold_splice.py` into the
**build-time copy** of `module_sf_noahlsm.F` that `kernels/Makefile` already makes for
the three warm splices.  The splice script fails the build if any anchor line does not
match exactly once, so a change in the WRF source cannot silently drop a hook.

| include | publishes |
|---|---|
| `noah_esm_cold_state.inc` | the module variables |
| `noah_esm_snopac_t12.inc` | `T12`, `T12A`, `T12B`, `DENOM`, `DTOT`, `DSOIL`, `ETANRG`, `ESNOW1/2`, `FLX1` — SNOPAC's snow-surface energy-balance closure |
| `noah_esm_snopac_cold.inc` / `_melt.inc` | which SNOPAC block ran |
| `noah_esm_snopac_end.inc` | `DF1`, `YY`, `ZZ1`, `EX`, `PRCP1`, `SNDENS`, `ESD`, `SNOMLT`, `FLX3` |
| `noah_esm_frh2o.inc` | FRH2O's iteration count and which of its three paths ran |
| `noah_esm_snksrc.inc` | per layer: `TAVG`, `TSNSR`, `FREE`, `XH2O`, `QTOT` |
| `noah_esm_hrt_tsurf.inc`, `_tbnd1.inc`, `_tbndk.inc` | `TSURF` and the layer-boundary temperatures `TBND` |

`noah_driver` zeroes all of them before each `SFLX` call, so a layer `SNKSRC` never
visits reads back as "not called" rather than as the previous call's value, and emits
them beside the existing outputs.

`SEH` and `T14` were deliberately **not** published: SNOPAC assigns them only inside its
melt block, so reading them on the sub-freezing path would have published an
uninitialised value — the class of mistake that cost the MOSAIC driver a day.

## What this does not cover

- **`FRH2O`'s Flerchinger fallback (path 3) never runs.**  Newton converged in at most
  **2** of its 10 iterations at all 332 layer-calls, and the fallback only fires when it
  fails at 10.  Nothing in these four columns approaches that, and the run logs contain
  zero `'Flerchinger USEd in NEW version'` lines.  A component may transcribe that path,
  but no test here pins it.
- **No real-terrain winter data.**  Snow under forest or over deep cold soil, and the
  `MODIS` land-use categories, are untested; so is any vegetation type other than
  dryland cropland and any soil other than silt loam.
- **The urban branch, `opt_thcnd = 2`, and `UA_PHYS`** are off, as in the warm run.
- **Glacial / permanent-ice points (`ICE = 1`)** are not sampled: `em_scm_xy` sets
  `xice = 0` and these cases use a land vegetation type.
- Melt here is driven by prescribed large-scale warm advection, which is how an SCM
  represents a warm air mass, not by resolved advection.
